# PDF 获取与科研通兜底

此流程仅为目标论文审读获取材料，不替代审读，也不保证能够获得全文。
使用当前实际可用的检索、浏览器和下载工具，不假设存在专用科研通接口。
用户要求“找全文/PDF 并解读”已授权公开检索；该授权不自动包含科研通发布或积分消耗。

## 有界公开检索

按顺序最多完成三个阶段，找到并核对可读 PDF 后立即停止搜索：

1. DOI 或精确标题检索：核对标题、作者、年份、DOI，检查出版社落地页和开放全文链接。标题有多个候选时先澄清，不猜 DOI。
2. 开放全文渠道：检查适用的 PMC、开放获取目录、预印本和机构仓储链接。说明预印本、作者接受稿与正式版本的区别。
3. 补充检索：最多三组不同查询，使用精确标题、标题变体、作者与年份组合，检查新找到的合理全文来源。

每阶段记录查询、已检查 URL、结果和原因（付费墙、无 PDF、论文不符、网络错误等），重复链接不算新证据。
不绕过付费墙、登录或验证码。暂时性网络错误最多重试一次；仍失败标为检索未完成，不归类为无全文。
没有可用检索工具时说明无法检索，不能声称已完成三阶段。若关键渠道未能检查，先请用户选择重试、提供材料或跳过未完成渠道进入求助，不能自动进入兜底。
完成适用阶段后只能说“在已检查渠道中未找到可获取的 PDF”，不能说互联网不存在该论文全文。

取得下载文件后验证它确为可读 PDF，而非登录 HTML、错误页或仅有补充材料；对照论文标题、作者、DOI/年份核对身份。
记录实际来源 URL、取得时间、版本和项目文件路径，不覆盖已有文件。只有摘要时可做明确标注的摘要分析，不能开展全文逐图审读。

## 第一张卡片：是否使用科研通

公开检索完成仍无 PDF（或用户明确选择跳过无法完成的渠道）后，用 `ask_user` 发卡片。
调用后结束当前轮等待下一条用户回答，不能以普通列表冒充卡片；取消、未答、关闭和超时都不是同意。
卡片中的“已检查”必须有检索记录支持；如有跳过渠道，将问题改为如实列出未完成渠道。

```json
{
  "question": "在已检查渠道中未找到可获取的 PDF。是否通过科研通发布文献求助？请先在默认浏览器登录科研通，并确保这是当前浏览器工具能够连接的同一会话。求助可能需要积分；继续只授权准备表单，提交及积分另行确认。",
  "options": [
    {"label": "已登录，继续准备求助", "description": "连接已登录会话，核对论文及页面积分要求，不立即提交"},
    {"label": "我自己提供 PDF", "description": "等待提供材料后继续审读"},
    {"label": "暂不继续", "description": "保留已核对的论文信息和检索记录"}
  ],
  "allow_freeform": true
}
```

用户自行在浏览器完成登录/验证码，不索取密码、验证码或 Cookie。默认浏览器登录不等于工具自动共享登录状态。
若工具无法连接该会话，明确暂停自动填写，提供求助入口和已核对的标题/DOI供用户手动操作，不声称已操作浏览器。
没有 `ask_user` 时说明交互卡片不可用，等待明确选择，不自动提交。

## 准备表单与积分确认

打开 https://www.ablesci.com/assist/create ，读取当前实际页面；登录后的字段和积分规则不得预设或凭记忆编造。
先检查当前账号是否已有相同 DOI（无 DOI 时使用核对后的标题/作者）的求助。已有求助时展示链接并沿用，不能重复发布。
若无法检查重复请求，说明原因并暂停提交，先让用户提供已有状态。
通过页面实际表单填写已核对的 DOI 与标题，核对自动补全没有换成另一篇论文；无 DOI 时不编造，必填缺失就暂停。
读取可见积分余额、页面列明的消耗/悬赏和提交条件。积分不足时暂停，不充值、不改悬赏、不接受额外收费。
无法确认本次积分数额或页面条件时暂停，不将未知消耗写成零。若页面允许设置积分，先取得用户给定的明确数额，再填入供确认。

表单准备好后通过第二张 `ask_user` 卡片展示实际标题、DOI、积分数额、可见余额及页面其他相关条件。
以下为参数模板；调用前必须将大括号占位内容替换为核实的实际值，不得将模板原样当作确认：

```json
{
  "question": "是否提交这次科研通文献求助？标题：{核对后的标题}；DOI：{实际 DOI 或无 DOI}；本次积分消耗/悬赏：{页面核实的数额及条件}；余额：{可见余额或页面未显示}。确认后将向科研通提交上述论文信息。",
  "options": [
    {"label": "确认本次信息及积分，提交求助", "description": "仅提交本次已展示的论文和积分条件"},
    {"label": "修改信息或积分", "description": "修改后重新展示具体信息等待确认"},
    {"label": "取消求助", "description": "不提交，不消耗积分"}
  ],
  "allow_freeform": true
}
```

调用后立即结束本轮。只有明确同意该论文及具体积分条件才提交一次；论文、积分或其他实质条件变化必须重新确认。
提交前复核表单，用户确认过的数额不是允许随意提高积分的预算。

## 提交结果与恢复

- 从成功页面或“我的求助”实际记录确认请求 ID/链接及状态，保存 DOI、标题、确认的积分条件和提交状态到项目工作记录；不得保存账号秘密。
- 超时或响应不明时记录“提交结果未知”，先查已有求助记录，不自动重试提交以免重复扣分。无法核实时请用户核实。
- 提交成功只代表“等待应助”，提供实际链接，不声称拿到 PDF，不启动全文审读。
- 不无限轮询。用户带回文件或明确要求检查进展时，查询既有请求；只有用户另行要求且环境支持才建立监测任务。
- PDF 可获取后下载并核对身份、版本、可读性和来源，再回到主 Skill 审读。错误论文或不可读文件不能进入证据分析。

浏览器自动化、登录态连接和站点表单会随环境变化；这些是模型执行规范，不是已实现的专用下载或提交适配器。
