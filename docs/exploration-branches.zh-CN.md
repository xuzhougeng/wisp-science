# 隔离探索分支

探索用于试验新的科研方向，同时不改变项目主线。它不同于普通对话分支：每个探索都有持久、独立的工作区，文件、Artifact、运行、决策和外部资源记录也保持私有。

## 创建和使用探索

1. 在 Wisp 原生会话中完成一轮对话。
2. 在任意已完成的 assistant 回复上选择**开始探索**，命名并创建。未回并的普通对话分支不显示该入口，请从 main 开始探索。
3. 正常使用探索。顶部 banner 会显示隔离等级，并提供**查看差异**、**设为主线**和**丢弃**。
4. 可从侧栏 source 会话下嵌套的行切换，也可点击创建检查点的 assistant 回复下方每个探索各自的卡片，在主线和多个兄弟探索之间切换。两处都可以收起，避免候选很多时占满会话列表或对话区：侧栏中点击 source 会话上的箭头，对话里点击**探索**标题。

第一个候选会开启一轮探索。此后从同一个所选回答创建的候选复用同一个不可变检查点，但各自拥有独立工作区和独立的检查点卡片。主线检查点提示和检查点卡片只显示在该 source 会话中，不会出现在同项目的其他会话。兄弟探索运行期间仍可继续创建候选；若多个创建请求同时到达，它们会在共享检查点初始化阶段排队，而不会报项目繁忙。探索轮开始后，source main 对话和所有由 Wisp 管理的主线项目写入都会被冻结。其他普通对话仍可用于讨论和只读检查，但不能修改项目状态。探索候选的输入框仍可通过 `#` 引用普通历史会话，Reader 会把只读检索结果加入当前轮次；兄弟探索的私有会话不会进入可引用范围。探索轮未结算前，source main 不能发送消息、创建新分支、移动到其他项目或被删除。探索候选内部不能再创建嵌套探索或普通对话分支；选定候选后，只把检查点之后的对话和项目产物并入原 main，随后原 main 可正常开启下一轮探索。

只有两种操作可以结算探索轮：**设为主线**会把一个候选并入原 main，并将包括所选候选在内的全部探索永久丢弃、清理隔离残留；原 main 的 frame ID、侧栏位置和普通对话分支关系保持不变。source main 右键菜单中的**放弃探索**则不并入任何增量，并永久清理全部候选。两条路径都必须等后端事务完成后才解除冻结。失败或单独丢弃某个候选，都不能结算探索轮或提前解除冻结。

Wisp 只在用户显式选择**开始探索**时记录不可变检查点：对话只归档到所选回答，工作区快照、Artifact heads、Runs、Decisions 和外部资源摘要则使用创建时的状态。历史回答探索不会恢复旧文件版本；隔离工作区从当前项目文件和记录开始，创建对话框会明确说明这一点。普通主线轮次不再自动创建探索快照。工作区 blob 仍按内容寻址复用；点击创建前由外部编辑器写入的文件也会进入快照。

快照扫描会按 Git ignore 语法读取各级 `.gitignore` 和项目内的 `.wispignore`，包括 `!` 反向规则。对于需要留在项目中、但不应进入探索历史的文件，可将规则写入 `.wispignore`。Wisp 还会在任意层级自动跳过 `.git`、`.pixi`、`.venv`、`node_modules`、`target`、Python 缓存以及内部 `.wisp` artifact/output 等明确的生成目录；`.github` 这类源码配置目录不会被一概排除。

强快照的上限为单文件 32 MiB、每个检查点合计 64 MiB 和 4,096 个文件；超出范围的内容会保存为明确的弱引用，而不是复制数据。扫描和 blob 写入均可取消。

每个已完成回复都有**开始探索**入口。一轮探索未结算时，只能从该轮选中的回答继续创建候选；提示条中的**再建一个探索**也始终使用该回答。主线的完整当前对话会被冻结并保留，设为主线时仅把候选新增的轮次追加到现有主线末尾，不重复继承前缀，也不替换所选回答之后已有的对话。若上下文压缩已移除所选历史模型上下文，创建会明确报告历史不可用，而不会误用后续轮次。ACP v1 没有服务端 fork，因此 ACP 会话不支持探索；ACP 绑定会话也不能绕过项目的探索冻结。

## 普通对话分支

普通对话分支在侧栏使用分支图标，也会直接显示在创建它的消息检查点下方。在侧栏中，探索、分支和子智能体沿同一条引导线一起列在来源会话下方，各自用不同的图标区分。来源会话上的箭头可一次收起全部；收起后该会话会显示隐藏的行数。当该会话或其下任一行处于打开、运行中或等待你处理的状态时，列表会自动展开；手动点击箭头后以手动选择为准。对话里检查点卡片上方有**分支**标题，点击即可收起或展开卡片。新建分支会继承来源会话当前所在的目录，在侧栏同一目录内嵌套显示于来源会话下；来源会话未归入目录时，分支也保持未分组。移动 main 到其他目录或未分组时，所有后代分支会一起移动，包括尚未加载到侧栏的分支。仍可单独移动分支及其后代到其他目录，不影响其上级会话或兄弟分支；再次移动 main 时，会将所有后代重新归入同一目录。分支建立后，main 可以继续向前推进；每个分支则拥有独立的后续上下文。

当分支完成聚焦任务后，右键选择**回并**。Wisp 只读取该分支从检查点之后新增的消息，并生成一份自包含的总结草稿。用户检查和编辑草稿后，确认文本会作为普通、可读的对话上下文追加到 main 当前末尾。main 在检查点之后新增的轮次不会参与比较，不会被截断、替换，也不会进入分支总结。

普通对话分支只有一层，并且只能回并一次。发送菜单和 `/fork` 只出现在 main 上；分支里不能再创建分支。回并后分支被冻结为只读历史：不能继续对话、再次创建分支、回溯或重复回并。main 中的总结不会在真实尾部铺开，而是以紧凑的**回并结果**卡片投影到该分支原来的检查点下方。点击卡片可查看完整 Markdown。该卡片只是展示层：底层 assistant 消息仍保留在真实追加位置，供后续模型直接检索。

回溯按总结真实追加的位置判断，而不是按卡片的视觉位置判断。main 回溯越过回并消息时，会撤销该次回并并重新开放分支；回溯越过分支检查点时，分支作为冻结历史保留，但不再挂在原消息下，也不能回并到已改写的 main。

总结草稿支持**重新生成**和**引导生成**。重新生成只依据检查点后的分支变更重新起草；引导生成会打开独立窗口接收用户引导词，并按【变更】【当前版本】【用户引导】三段上下文生成新版本。新版本只替换待确认草稿，不会自动写入 main。

单个分支仍可使用**删除分支**。只要 main 仍有普通对话分支，main 本身就不能被删除，必须先删除这些分支。原来的**比较分支**、**转为独立会话**以及会改写共同祖先并清理整个分支家族的收敛动作，已不再属于普通对话分支流程。

这些操作只处理对话历史，不会合并、恢复或回滚项目文件、Run、Artifact 与外部副作用。如果需要一起比较并晋升项目级变化，请使用隔离探索。

## 设为主线

**设为主线**会把所选探索相对检查点的补丁应用到原 main。只有所选探索没有活动 Run 或不支持的引用变化，并且实时项目目录没有改动该补丁涉及的同一路径时才能执行。

确认前应检查五类差异：

- 文件
- Artifact
- 运行
- 决策
- 外部副作用

探索期间，Wisp 会冻结 source 对话和受管理的项目状态。外部编辑器和进程不受这个锁控制，因此晋升前仍会重新扫描项目，并核对 source 对话、Artifact heads 和项目实体。若实时项目目录与所选探索改动了同一个文件路径，晋升会因冲突而拒绝；其他会话或外部进程产生的非重叠文件不会出现在冲突预览里，会原样保留，也不会阻止探索补丁合入。成功时只把所选探索在检查点之后新增的对话记录追加到原 main，不会重复克隆的检查点历史，也不会自动解决重叠文件冲突。

如果自动晋升仅因主线变化或引用文件变化而停止，差异窗口会提供**手动解决文件冲突**。打开主线和探索两个文件夹，在编辑器或差异工具中比较，并把需要的文件复制或合并到实时主线文件夹；随后选择**完成手动解决**，Wisp 会保留主线文件夹的当前内容，并永久清理本轮全部候选。这个兜底流程不会绕过晋升 guard，也不会自动迁移探索私有的对话、Artifact head、Run、研究记录、外部资源注册或外部副作用；完成前应另行保存这些信息。活动 turn、终端或 Run 仍须先结束，才能清理探索轮。

## 隔离与外部副作用

普通项目文件会复制到探索工作区，不使用可写 hard link；被 ignore 的路径不会进入快照。符号链接、device、socket、Git 元数据以及因大小或总预算而保留的引用文件可能显示为“部分隔离”。本地弱引用以项目相对路径、大小和修改时间识别；复制到探索工作区后，绝对根路径自然变化不会被误判为修改，但已有弱引用的大小或修改时间变化仍会阻止 fast-forward。探索中新生成的大型本地文件会在晋升预检中计算校验和，并通过可回滚文件事务设为主线。远程或不支持的引用目标发生变化也会阻止 fast-forward。

探索中的本地文件读取和搜索只能访问隔离工作区。若 shell 命令、本地或 WSL 后台 Run、本地或 WSL Python/R 代码以绝对路径指向实时主线工作区（包括 Windows 盘符对应的 `/mnt/<drive>/...` WSL 路径），Wisp 会拒绝执行。应使用项目相对路径，使执行目标落在探索工作区内；即使启用 Full Permission，也不能绕过这条边界。

远程作业、邮件、数据库写入、MCP/App 写操作和其他网络副作用无法通过丢弃探索来撤销。Wisp 会记录并在执行前警告，但不会声称能够回滚这些操作。

单独丢弃候选只删除它的私有记录和经过严格校验的 app-data 工作区，但探索轮仍未结算，source main 继续冻结。必须选择一个候选，或右键 source main 选择**放弃探索**，才能结算本轮。两条路径都会清理全部探索候选；选择会把所选候选的增量并入原 main，放弃则让原 main 保持在检查点状态。

产物面板只展示用户工作区中的逻辑路径，不展示 Wisp 内部的 `.wisp` 快照存储路径；逻辑路径任一层为隐藏项的产物不会出现在产品界面中。
