# SwiftUI / WebView 下一阶段 UI 对齐计划

日期：2026-09-28。基线：`9ea5f411f7b90f4ba8c44f698f84ce0f7086e7b5`，1.15.0，macOS arm64 debug。本轮完成构建与审计，不包含产品 UI 实现。

## 决策

以 WebView 的任务路径、信息层级和状态含义作为默认基准，SwiftUI 保留原生窗口、文本选择、文件选择器与辅助功能。先对齐正确性和可见信息，再对齐尺寸、密度及控件外观。

下一阶段按 A–J 划分小 PR：**设置语义、对话阅读、输入能力、面板、研究历程、日历、论文证据只读工作区、设置列表、首页/搜索/弹窗、工作流只读结构**。具体交付顺序以下述三批为准。B 的公式渲染、C 的能力接入、H 的多类设置都继续拆分，不做一个大型“原生 UI 重写”PR。

首批交付 A、B1、B2、D1；C 先完成能力契约核查再排实施。E–G 作为第二批研究页面，H–J 作为第三批。论文证据写操作、工作流画布编辑和科学 viewer 不混入视觉对齐 PR。

## 分批 PR 与验收

### A：设置语义和字段完整性（P1）

位置：`NativeSettingsView.swift`、`NativeSettingsModel.swift`、设置资源导出、`ui/src/settings_view.rs` 作为行为参照。

1. 校正 auto_continue 及次数上限说明；补 `semantic_compact_on_model_switch`、`semantic_compact_idle_hours`，明确 disabled/hidden 约定。
2. 说明全局、项目、新会话、下一轮、重启生效的范围；常规页标清分组保存范围，复核同步后端选择器的初始值。
3. 用同一 settings fixture 验证读、改、保存、取消；未展示/未知字段 round-trip 保留。只修 UI 与适配层，不更改 agent 运行规则。

验收：双端相同值显示相同含义；自动继续关闭时能理解上限；0/默认值/非法数值有测试；退出未保存状态按既有策略执行。

### B1：消息排版与可用动作（P1）

位置：`NativeMarkdownContent.swift`、`NativeSelectableMessage.swift`、`NativeConversationView.swift`、`ProjectWorkspace.swift`。

分开提交：阅读块（标题/代码高亮/只读任务框/引用/表格）与动作行（时间、复制、可接入动作）。完整记录/模型视角先核对现有查询契约；缺能力时另列任务，不显示假按钮。

验收：相同 fixture 覆盖长代码、宽表、中英混排；复制源文准确、跨块选择保留、只读任务框不会写消息；动作点击不误发送、不破坏选区。

验收：未启动/运行/断连/只读状态、切换会话草稿、附件取消、Enter/Cmd+Enter/Shift+Enter 和真实 IME；运行中停止与排队不因外观变更退化。

### H1–H5：设置视觉系统（P2，每组一个小 PR）

## 每批共同门槛

- 每个 PR 开工先固定源码 revision、fixture ID、选中项目/会话、视图偏好；截图归档用与此次相同的命名体系。
- 配对窗口目标 1100×760，另取两端共同可达的窄窗（实际记录尺寸）；浅/深、中/英。以内容坐标比较骨架；系统标题栏、字体抗锯齿不进入像素阈值。布局阈值应在同尺寸基线建立后定义。
- 对每个行为变更补相关 Swift/宿主/Playwright 测试，截图不替代语义断言。接口变化遵循 `wisp-dto` 和合同测试；无真实 API/SSH/GPU/WSL 依赖。
- 按 AGENTS.md：定向测试后 `cargo fmt --all -- --check`、`cargo test --workspace`；UI/Tauri 修改补 wasm check、`npm ci && npx playwright test` 和受影响 Swift 测试；MCP 修改才追加 smoke。
- 真正完成需同 fixture 成功态/空态/加载态/失败态与交互验收；没覆盖的状态写“未验证”，不能沿用过去截图宣布通过。
