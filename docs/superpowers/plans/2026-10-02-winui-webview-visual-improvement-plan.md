# WinUI 3 与 WebView 界面对比及改进计划

日期：2026-10-02。状态：实施中，完整补齐尚未完成。

WinUI 3 已具备主要工作入口。下一阶段应先改善聊天区域的空间分配、输入区组织、报告阅读和刷新稳定性，再深化终端与研究页面。沿用现有共享色板、图标与原生控件，把 WebView 已验证的内容层级和交互行为带到 Windows。

- 当前源码基线为 `12494fb5ecee01464c260518cd2b8d4936c6d95e`。本轮逐项核对了 `apps/windows`、`ui`、相关测试及已有计划。

- 当前工作区另有未提交的 WebView 模型设置与输入区修改。本计划保留这些修改；实施输入区对齐前，应重新确认最终合入的行为基线。
- 两端旧截图的裁剪、分辨率、字体偏好与 DPI 未统一，不能据此断言 WinUI 字号小了多少、页面浪费了多少百分比空间。

## 已完成能力应保留

当前源码已有表格、代码高亮与复制、本地图、紧凑 usage、消息复制、产物分组和图片预览、笔记本输出、运行时面板、委派入口、会话菜单与置顶、环境跳转及一组 slash 导航命令。设置已有 20 个分类、同窗口导航、草稿保护与字号绑定。

WinUI 也已有首页堆叠、工具条换行、侧栏缩窄和设置预览换行。问题主要在于三栏宽度分配、控件层级和动态状态保持，不能将其描述为完全没有响应式或只有空壳按钮。

## 页面差异与改进方向

下表记录本轮实施前的差距；工作区内已实现的项目及待验收状态见“当前执行记录”，不要将此表当作实现后的现状。

| 区域 | WebView 基线 | WinUI 当前实现与影响 | 改进方向 |
| --- | --- | --- | --- |
| 主工作区 | 消息、输入区与运行条共用自适应列宽，上限 1280 CSS px；窄窗右栏变抽屉 | 对话及输入上限 850 DIP，侧栏 218 或 244 DIP，右栏固定 320 DIP；同时展开时中栏可用空间明显减少 | 按可用中心宽度分配列宽，统一阅读与输入边界；右栏允许调整宽度并在小窗覆盖显示 |
| 输入区 | 单一输入容器组织附件、模型、思考强度和发送状态；有候选菜单 | 多排按钮、输入框、模型行与外置提示构成表单；slash 输入时展示完整命令串；跟随复选框常驻 | 合并为紧凑输入容器，保留清晰主动作；slash 用可搜索候选列表，状态按需显示 |
| 消息阅读 | 已完成轮次突出最终回答，过程可折叠；动作更轻 | 每条事件单独排版，非工具消息常驻复制、引用、收藏；工具摘要取结果前 180 字 | 按轮次组织回答与过程，区分标题、正文、元信息；次要动作弱化，保持键盘可达 |
| 阅读稳定性 | 已有滚动跟随与报告折叠场景测试 | 刷新时清空并重建消息；展开态重新按失败状态初始化。存在阅读位置、展开与选区被打断的结构性风险，尚未实机复现 | 按稳定消息标识更新，保存用户展开状态和滚动锚点；只在跟随状态滚到底部 |
| 工作区面板 | 页签、筛选、类型预览及窄窗抽屉相互配合 | 已有分组、预览和可横向滚动页签；按钮未绑定当前选中态，面板固定宽度 | 明确当前页签，统一标题和筛选层级，保留每页滚动与筛选状态 |
| 设置 | 搜索与分类导航；字段按任务组织 | 已有分类和自适应外观预览；缺少同等设置搜索；外观页与其他表单使用不同宽度和内边距 | 增加搜索，统一标题起点、字段间距、说明及保存状态，保留主窗口内导航 |
| 研究历程与论文证据 | 日期组织、记录详情、来源和相关运行形成导航链 | 历程主要是日期筛选和文本记录；论文证据覆盖初始创建及只读条目 | 先优化日期分组、记录类型、来源与返回路径；编辑、证据绑定及复现另拆协议任务 |
| 终端及富预览 | xterm.js 与专用 viewer | 终端仍为文本输出和按行输入，高度固定 260 DIP；常规预览主要覆盖文本和图片 | 延续既有 W6 技术方向，分别交付嵌入式终端与只读富预览 |
| 首页与侧栏 | 项目、最近会话、分组和动作层级较完整 | 核心入口已齐，卡片和侧栏仍可统一密度与命名 | 在聊天主链路稳定后统一卡片、相对时间、状态及溢出菜单 |

## 建议的界面规则

以下数值是实施起点，需由同条件截图确认，不能当作已经验收的设计指标。

- 聊天、审批、运行状态和输入区共用一个宽度计算。宽屏可参考 WebView 的 1280 上限；窄屏优先使用有效宽度，内侧留白以 16 至 24 DIP 为起点。同步处理实时会话与只读历史展示。
- 保留现有断点逻辑，但增加三栏预算：若显示右栏后中心有效宽度小于约 560 DIP，优先将右栏改为覆盖抽屉；更窄时侧栏可折叠。抽屉关闭后恢复原面板状态。
- 输入区主视觉为文本和发送动作。附件显示可移除条目，模型与环境位于紧凑工具栏；排队、断连、审批、发送不确定分别有明确状态。将“跟随最新回复”改为滚离底部后可见的“回到最新”入口。
- 普通回复使用舒适行距和清晰段落，用户输入、最终回答、工具过程、错误与 usage 有不同层级。过程默认折叠时仍显示运行中、失败及待审批状态；不把失败埋进已完成摘要。
- 使用现有色板与 `compose_icon` 同步资源，补少量尺寸和间距规则。原生键盘焦点、选择、输入法和可访问性行为继续保留，不为视觉一致性重新实现原生输入控件。
- 次要动作可在悬停或键盘聚焦时突出，始终有可访问名称与键盘入口；当前页签、当前分类与键盘焦点要能区分。
