# SwiftUI 与 WebView UI 对齐计划

日期：2026-09-26。本文保留最初的 Computer Use 审计与分批计划；后续已开始实现，进度和验收见 [实施记录](2026-09-26-swiftui-webview-ui-alignment-implementation.md)。

## 结论与对齐方向

以 WebView 的信息层级、阅读密度、动作位置和文案作为默认基准，SwiftUI 保留原生窗口、系统文件选择器、键盘/辅助功能与文字选择能力。对齐的是可见信息及任务路径，不要求操作系统控件逐像素相同。

优先顺序：可重复基线 → 工作区骨架 → 输入区 → 消息阅读 → 产物面板 → 设置 → 首页。公式与产物差异属于能力/数据路径问题，单独交付，不能用样式调整冒充修复。沿用小 PR 原则，不重做整个原生壳。

## 已观察差异

| 区域 | SwiftUI 实际表现 | WebView 实际表现 | 对齐目标 |
| --- | --- | --- | --- |
| 工作区侧栏 | 新建会话为实心绿色主按钮；导航更紧凑，字体视觉更小/更重；底部显示路径 | 新建会话为普通导航项并显示快捷键；导航更疏；底部有技能/MCP/记忆计数 | 统一行高、字重、选中态、快捷键与信息位置；路径提供可达入口 |
| 会话列表 | 当前样本无“今天”分组标题；排序与 WebView 不同 | 有时间分组及会话操作入口 | 相同数据和排序偏好下比较；先排除数据与偏好差异，再对齐分组和菜单 |
| 顶部工具栏 | 标题旁常驻改名/置顶/删除；较矮、紧凑；无可见完整记录/模型视角切换 | 标题以标签呈现；右侧有记录视角切换和成组工具 | 统一工具顺序、分组、名称和溢出规则；破坏性动作收入会话菜单 |
| 输入区 | 大面积空白，无可见输入提示；附件为文字按钮；模型选择与发送较简单；下方常驻跟随勾选 | 有 @/#/slash 提示、Local/Python/R 状态条、附件/Agent/Fast/模型/发送选项 | 先统一尺寸、占位文案与动作布局，再接入有真实能力支撑的入口 |
| 正文排版 | 内容较紧凑，代码近似灰底文本行；任务状态显示为文字；引用缺少 WebView 的竖线层级 | 代码有高亮和可见复制按钮，任务复选框、引用竖线和更明确的块间距 | 标题/正文/表格/代码/引用/任务列表共享语义和视觉规范 |
| 公式 | 行内 `$...$` 与块级 `$$...$$` 显示为源码 | 显示排版后的公式 | 公式渲染单列能力 PR，保留源码复制与失败回退 |
| 消息动作 | 当前消息下未见对应 WebView 的完整动作行 | 可见复制、分支等动作及“已生成 · 2” | 建立动作能力表，先补可用动作的可发现性；不假装未接入能力可用 |
| 产物面板 | 当前会话显示空；面板约 320 宽；含筛选框；标签称“代理/执行环境” | 显示公式/表格两项；面板约 400 宽；分类卡片；标签称“Agents/环境” | 核对派生产物来源、持久产物与会话关联；统一文案、宽度策略、分类和计数 |
| 设置 | 分类大体一致；常规合并“工作区与通知”；发送方式为开关，帮助文字较少；网络在环境前 | 工作区交互与通知更新分组；发送方式为下拉；有解释与取消入口；环境在网络前 | 统一分组、帮助文案、保存/取消语义，原生控件类型可保留合理差异 |
| 首页 | 有品牌、双列项目/最近会话；卡片显露星标/设置；最近会话状态右对齐；有预览诊断页脚 | 还可见文档、示例项目；卡片显露导出/新窗口/删除；状态为徽标 | 统一入口发现方式、卡片元数据和状态；诊断工具移入开发专属位置 |

未在当前界面看到入口不等于后端缺失。菜单、右键和其他页面中的替代路径需在实现前核对。原生代码/表格右键复制已有历史实现记录，本轮差异是可见按钮和发现成本，不是断言无法复制。

## 实施批次与验收

### PR 0：固定对照基线（P0，后续依赖）

从同一稳定提交构建两端，记录 shell/helper/WebView revision、主题、语言、显示缩放与窗口尺寸。准备可重置的独立 fixture，确保会话、消息、持久产物和排序偏好一致；记录正文派生产物是否属于不同来源。

建立页面状态清单：主页、空会话、富文本、侧面板、设置、单层及嵌套弹窗。配对截图使用 1100×768 和 900×700，明暗/中英作为覆盖矩阵。这些尺寸是建议验收条件，实施时需确认两端最小窗口限制。

验收：每条差异标记为“最新构建复现 / 已消失 / 数据或偏好差异 / 未确认”，不给旧包结果直接开实现工单。

### PR 1：工作区布局与工具栏（P1）

在现有设计资源同步机制上统一字体角色、行高、内外边距、圆角、边框、图标尺寸、选中/悬浮/禁用态。优先调整侧栏、标题区、工具栏和面板分隔。图标沿用共享图标资源和 `compose_icon()` 对应语义，不新增独立图标体系。

主要位置：`NativeConversationView.swift`、`NativePanelView.swift`、`scripts/sync_native_design.py`，以及 WebView 的 `ui/src/app_support/messages.rs`。先确认已有资源定义，不因文件长度拆分模块。

验收：常规/窄窗下标题可截断但操作可达；菜单动作顺序一致；删除进入明确菜单/确认；关闭侧栏、打开面板不遮住发送按钮；关键结构边界对照偏差目标不超过 4 pt，字体抗锯齿和原生控件系统差异不纳入像素阈值。

### PR 2：输入框视觉与状态（P1）

统一空白输入框高度、内边距、占位说明、附件、模型与发送动作位置，减少原生大块空白。支持自适应输入高度和可见的附件状态。随后单独按能力接入运行时状态条及 Agent/Fast/发送选项，避免画出没有行为的按钮。@/#/slash 文案仅在对应交互可用后显示。

主要位置：`NativeConversationView.swift`、原生输入组件与 `ui/src/app_support/composer.rs`。

验收：空输入/长输入/附件/停止/禁用状态可辨；Enter、Cmd+Enter、Shift+Enter、IME、切换会话草稿保持分别有测试和实机步骤。不得因视觉改动改变发送语义。

### PR 3a：消息阅读与动作（P1）

在 `NativeMarkdownContent.swift` 和 `NativeSelectableMessage.swift` 对齐正文宽度、字号、行距、块间距、表格 padding、代码容器、任务列表、引用样式；代码/表格增加可见复制入口并保留右键路径。核对消息时间和可用动作，保持跨块选择与辅助功能。

验收：固定富文本 fixture 逐块对照；长代码不撑破布局；表格横向溢出可访问；复制内容准确；点击操作不丢失选择；长消息滚动不会被输入框覆盖。

### PR 3b：公式渲染（P1，独立技术选择）

评估原生公式渲染方案、依赖许可、离线资源与辅助功能；按行内/块级/错误输入/长公式实现。技术选择形成小规格后再接入，保留原文，不能用图片替换导致无法复制或阅读。

验收：合成公式正确显示，复制仍得到原始 LaTeX；无网络可用；非法公式有明确回退；明暗主题、缩放和窄窗可读。

### PR 4：产物面板与预览（P1）

先追踪本次“WebView 2 项、原生 0 项”到底是数据库差异、消息派生产物索引缺失，还是展示遗漏。确认来源后复用共享 DTO/现有解析能力；如涉及跨边界形状，在 `wisp-dto` 定义。持久产物与派生内容明确区分，不重复写入。

随后统一标签名称、计数、宽度、列表/网格状态、分类卡片、空态与加载态。范围限定为表格/公式，其他科学 viewer 保留后续计划。

验收：相同 fixture 两端同一来源的计数和内容一致，点击能预览；切换会话不残留旧产物；失败与真正空数据可区分。

### PR 5：常规设置对齐（P2）

保持现有分类契约，优先统一常规页分组、说明文本、发送偏好表达、环境/网络顺序和保存范围。原生允许系统开关/选择器，但操作效果及取消/未保存状态必须清楚。后续其他设置页逐页审计，不能从常规页推断全部已对齐。

主要位置：`NativeSettingsView.swift`、`ui/src/settings_view.rs`、`scripts/sync_native_settings_contract.py`。

验收：两端相同偏好含义和生效时点一致；未保存离开有既定策略；取消不写入；帮助文字完整；长中文/英文布局无截断关键内容。

### PR 6：首页与剩余表面（P2）

对齐首页内容最大宽度、品牌比例、项目卡片元数据、状态徽标和动作可达性，补齐文档/示例入口或明确替代路径。预览诊断信息保留在开发模式。后续另批审计空态、搜索、文件预览、论文证据、研究历程和审批等未覆盖页面。

验收：首页同数据对照；项目动作可键盘访问；窄窗重排不横向溢出；长标题/路径可截断并有完整信息入口。

## 测试与完成标准

- 每个行为变更补定向 Swift/宿主/Playwright 测试；视觉改动有对应布局断言和同 fixture 配对截图，不能只证明截图生成成功。
- 所有可关闭层遵守窗口级 Escape 栈；测试打开后立即按 Escape，不先移焦点；嵌套时一次只关闭最上层，父层保留。
- 每个实现 PR 先跑最窄相关测试，再完成仓库要求的 `cargo fmt --all -- --check`、`cargo test --workspace`；涉及 UI/Tauri 时运行 wasm check 与完整 Playwright，并运行受影响 Swift 测试。MCP 修改才追加 smoke。
- 按批次记录源码 revision、fixture、步骤、截图和实际结果；自动化、离屏渲染、Computer Use 分开计数。尚未验证的状态不得标为完成。
- 本轮仅新增计划文档，没有产品行为修改，未运行产品测试；Computer Use 观察不是最新源码的回归结论。
