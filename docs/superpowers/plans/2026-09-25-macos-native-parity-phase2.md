# macOS 原生对齐：第二阶段目标

2026-09-26 范围更新：按用户要求，本阶段排除 ACP。起点为已包含 #1361、#1362 的 main `f684c799`，实施分支 `codex/native-reliability-phase2`。

## 阶段目标

让原生项目同步、目录导入和消息输入在取消、冲突和失败场景下可靠工作，完成遗留的 Computer Use 验收，并建立可重复的质量基线。ACP 的实现、修复与专项验收不纳入本阶段；相关长期事项保留在总清单中。

本阶段结束的依据是下表中的操作结果、自动化与实机证据齐全。PR 合并、入口存在、协议测试和离屏渲染分别记录，不互相替代。

## 执行顺序与验收

| 顺序 | 交付 | 验收标准 |
| --- | --- | --- |
| 1 | 项目同步冲突闭环 | 分别验证保留本地/采用远端的确认、立即 Escape、取消、成功与失败；取消不改快照，失败保留选择且不自动重试，成功状态经独立读取确认。继续使用隔离本地 fixture，明确区分同内容分叉与不同内容冲突，不宣称真实云盘或双设备通过。 |
| 2 | 项目目录导入收尾 | 旧格式目录通过原生实际登记并可读；文件选择器打开后不先移焦点，第一次 Escape 只关闭选择器，父导入弹窗保留。当前格式登记已有证据，保留路径与项目身份一致的约束。 |
| 3 | 实机输入一致性 | 两种发送偏好分别验证 Enter/Cmd+Enter/Shift+Enter、中文 IME 候选确认、快速全选粘贴后发送；不得误发旧草稿、重复发送或丢失输入。切换会话、权限等待、重开窗口后草稿仍正确。若复现缺陷，独立修复并回归。 |
| 4 | 稳定版本回归与基线 | 在同一稳定产品代码上完成 Rust、Swift、wasm、Playwright 和标准 QA 构建；同 fixture 的浅/深色、中/英文及常规/窄窗配对截图覆盖上述路径，核对布局和操作可达性；重复记录 35-turn 会话首次打开、切换、滚动和 idle CPU，保留机器/窗口/负载条件，不预设性能胜负。 |

每项独立小 PR；一个验收任务若暴露多个无关缺陷，按具体行为继续拆分。先完成第 1 项，再推进项目和输入，最后在稳定代码上收口回归，避免编译期间继续修改共享 DTO。不要重跑或重复提交结果未知的导入、删除、同步操作。

## 交付物与完成条件

- 上述已复现缺陷有对应测试，所有修复通过相关回归。
- 所有实机验收保存精确的 shell/helper revision、fixture、步骤、截图和实际结果；新旧构建的证据不混用。
- 完成合并后代码的完整回归；中断前仍在运行的旧分支测试只作为该源码的证据。
- 质量基线可重复执行；若存在未解决失败，明确记录复现步骤与影响，本阶段保持未完成。
- 更新原生能力文档与总进度清单，不把全部长期 parity 目标一并标为完成。

## 后续阶段保留

本阶段完成后，优先补会话跨项目复制/移动、归档导出、分支导航，以及 plan mode 决策和普通工具授权范围。之后依次推进论文/revision 与证据操作、@/#/slash 与上下文操作、公式/图片与分类文件预览。

首次使用、完整原生壳/helper 升级及失败恢复、签名/公证/安装另设交付阶段。真实 OAuth 登录、真实云盘和正式发布均不作为本阶段自动化前提；保留既有 keyring 和隔离测试约束。
