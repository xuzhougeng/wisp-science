# 项目数据库不可用时的安全排查

如果打开项目或会话时看到 `Project <id> database is unavailable: <path>`，Wisp 当前无法访问错误中所列路径的项目数据库。这个错误本身不能说明数据库一定损坏，也不能说明其他项目的会话数据库已经损坏；常见原因包括工作区被移动、磁盘或同步盘暂时不可用、权限变化，或上次写入未正常结束。

## 先保护数据

1. 完全退出 Wisp，确认应用已关闭。
2. 将整个项目目录（至少包括 `.wisp`）复制到另一个位置。保留 `project.sqlite` 以及旁边可能存在的 `project.sqlite-wal`、`project.sqlite-shm` 或 journal 文件。不要只复制主数据库文件，也不要删除、重命名或覆盖这些文件来尝试“重建”数据库。
3. 如果项目位于外接盘、网络盘或同步目录，先确认该卷已挂载、同步已完成，并且当前用户对项目目录有读写权限。检查错误提示中的路径是否仍是项目的真实位置；若移动过项目，通过 Wisp 的项目管理入口重新打开其当前文件夹。

## 尝试恢复会话

在备份完成后，使用 **导入项目 → 从工作区恢复会话**，从原工作区 `.wisp/history` 中恢复可用的历史快照。此功能是尽力恢复：它只能导入确实保存在这些快照中的消息，不能替代完整项目数据库备份，也不一定包含普通对话或项目级记录。完整迁移应使用 Wisp 的项目 ZIP 导出/导入。详见[项目迁移说明](project-transfer.md)。

若错误仍在，保留原始目录和备份，记录 Wisp 版本、操作系统版本、项目是否曾移动/同步、错误路径，以及 `.wisp` 中数据库和旁路文件的文件名与大小，并随 issue 提交。不要将数据库文件上传到公开 issue，因为其中可能包含私人会话内容。

## 关于“任何会话都打不开”

如果只有一个项目报错，先从项目首页打开另一个项目，确认故障是否局限于该项目。如果其他项目也无法打开会话，请在 issue 中注明跨项目影响，并附上各项目对应的错误路径。单个项目数据库不可用不应被直接推断为所有会话数据都已丢失；维护者需要根据 Wisp 版本和日志确认会话库与项目库之间的依赖关系。

目前没有足够的公开数据判断这种故障发生频率，因此不能仅凭一条报错称它为常见问题。
