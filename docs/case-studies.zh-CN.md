# Wisp Science Case Study 选题库

> 状态：候选案例，不代表已经完成或验证的科研成果
> 调研日期：2026-08-09

这份文档提出 10 个适合 Wisp Science 的 case study。它们不是功能清单，
而是从一个真实科研问题出发，经过检索、计算、判断和复核，最后留下可检查
产物的完整研究故事。每个案例都应尽量使用公开或合成数据，使任何人无需
私有数据库、真实 SSH 主机或湿实验条件也能复现演示的核心部分。

## 从同类产品中学到什么

- [Robin](https://www.futurehouse.org/research/demonstrating-end-to-end-scientific-discovery-with-robin-a-multi-agent-system)
  最值得学习的不是“全自动科学家”这个标签，而是文献检索、假设生成、实验设计、
  数据分析和下一轮实验之间形成了连续闭环；湿实验由人执行，AI 负责保持研究逻辑连贯。
- [Biomni](https://biomni.stanford.edu/) 把大量生物医学工具、数据库和软件放进同一
  执行环境，用具体任务证明价值，例如 CRISPR 筛选设计、单细胞注释、ADMET 预测、
  变异解释和克隆方案设计。其[论文](https://biomni.stanford.edu/paper.pdf)和
  [开源仓库](https://github.com/snap-stanford/biomni)也表明，案例必须给出实际输入、
  工具轨迹和可核查输出，而不能只展示一段自然语言回答。
- [Claude Science](https://www.anthropic.com/news/claude-science-ai-workbench) 把本地或
  SSH/HPC 计算、领域 Skills、多 Agent、审阅者、探索分支、图表和稿件产物放进一个
  工作台，并强调每个结果都要能回到代码、环境和历史。
- [Claude for Life Sciences](https://www.anthropic.com/news/claude-for-life-sciences)
  进一步说明，真正有用的科学 Agent 需要连接论文、数据库、实验记录和分析软件，并把
  可复用流程固化成 Skills，而不是只靠模型记忆回答问题。

Wisp Science 不需要逐项模仿。更鲜明的定位应该是：**开源、本地优先、模型可替换，
把项目文件、执行环境、Run、Artifact、论文证据和研究决策保留在用户自己的控制面中。**

| 5 | 为 T 细胞耗竭设计可审查的 CRISPR 筛选 | 多数据库证据如何变成可执行实验设计 | 公开文献、基因集与参考基因组 | P1 |

| 7 | 从公开结构到可引用的功能位点报告 | 本地编排、MCP 检索、作图与叙事 | 一个公开 PDB 结构 | P1 |

| 9 | 一条争议性结论的正反证据地图 | 多 Agent 不是“多写几份摘要”，而是独立取证与交叉审阅 | 50–100 篇公开文献 | P1 |

## 1. 从 GEO 原始计数到可复核论文证据

**研究问题**

在公开数据集 GSE153250 中，敲低 ESR1 后哪些通路发生稳定变化，这些变化能否支持
一个清晰、可检验的后续机制假设？

**示例提示**

> 找到 GSE153250 的样本和计数数据，比较 siESR1 与 siNT，完成 QC、DEG、ORA/GSEA，
> 生成一张主图和 Methods 草稿。所有结论都要绑定到数据、代码、Run 或文献证据；
> 最后冻结一个可验证的 Evidence Capsule。

**演示路径**

1. 通过 GEO/PubMed 工具确认 accession、样本设计和原始论文，生成不可猜测的 sample sheet。
2. 在持久 Python 或 R 环境中完成 QC、归一化、差异表达和通路分析。
3. 把分析拆成 `QC → DEG → ORA/GSEA → figure` 的可复现模块，记录参数、包版本和数据库版本。
4. 由独立 Reviewer 检查样本分组、统计数字、图表与正文陈述是否一致。
5. 生成主图、结果表、Methods 和带精确证据绑定的 Publication Revision，再执行一次干净复核。

**最终产物**

- `sample-sheet.csv`、分析脚本、环境快照和完整 Run 日志；
- DEG/通路表、一张 publication-ready 多面板图、Methods 与 Results 草稿；
- 可导出的 Evidence Capsule。

**验收标准**

- 样本映射能够回到 GEO 元数据，不由模型臆测；
- 关键 DEG 数量、效应方向和图中数值可由脚本重新生成；
- 干净复核通过，或明确报告环境不一致和未通过项；
- 机制部分使用“数据支持的假设”，不写成已经验证的因果结论。

**为什么适合 Wisp**

仓库已经包含按研究顺序组织的 ESR1/GSE153250 seed 会话。这个案例可以把已有五段
演示升级为一个真正端到端、可下载、可复核的旗舰故事，并直接展示
[Publication Evidence](publication-evidence.md) 的差异化价值。

## 2. 留在实验室服务器上的单细胞图谱

**研究问题**

两个批次的 PBMC 单细胞数据能否在不过度校正的前提下整合，并得到有证据支持的
major cell type 注释？

**示例提示**

> 原始 `.h5ad` 在已注册的 SSH 服务器上，不要下载到本机。先做 QC，再分别用
> Scanpy 标准流程和一个 Harmony/PCA 基线进行整合与注释；把两条路线放在独立探索分支中，比较
> 批次混合、标记基因保留和稳定性后再推荐主线方案。

**演示路径**

1. Probe 已注册执行环境，确认 Python、GPU、磁盘和解释器路径。
2. 在远端原位加载数据，先生成低敏感度的 QC 汇总和小型预览 Artifact。
3. 从同一项目检查点创建两个 [exploration branches](exploration-branches.md)：
   Scanpy 标准流程与经典 PCA/Harmony 或等价基线。
4. 用相同指标比较批次效应、细胞类型可分性、marker 保真度和随机种子稳定性。
5. Reviewer 审计原始 counts 是否被误用、是否发生 label leakage，以及结论是否超出指标。

**最终产物**

- 两套方法的 UMAP、QC 表、marker dot plot 和指标对照表；
- 远程 Run 的环境与日志快照；
- 一份“为什么选择该整合策略”的 Decision 记录。

**验收标准**

- 原始矩阵不离开 SSH 主机，文档中只使用聚合指标和经批准的预览；
- 两条方法路线共享同一输入与评价指标；
- 一次只把胜出分支 fast-forward 为主线，另一分支仍可审查；
- 明确说明细胞注释是计算推断，需要领域专家复核。

**为什么适合 Wisp**

这个案例同时用到 Execution Context、持久运行时、远程 Run、探索分支、
`analysis-workflow` 和审阅流程，最能把“本地优先”解释为数据位置与计算权限的控制，而不只是桌面应用。

## 3. 复现论文图 2，并审计它支撑的结论

**研究问题**

一篇开放论文的关键图是否能从作者公开数据和方法描述中重建？重建后的统计量是否真的
支持正文中的核心 claim？

**示例提示**

> 阅读论文和补充材料，定位 Figure 2 的数据来源、过滤规则、统计检验和作图参数。
> 在隔离模块中重建该图；不要追求像素级模仿，优先核对样本数、效应量、置信区间和
> 统计定义。最后列出“复现成功”“近似复现”“无法判断”的项目。

**演示路径**

1. 从 PDF、补充材料和数据仓库建立 figure-to-source 清单。
2. 将正文 claim 拆成可检验断言，并绑定到图中 panel、表格或方法段落。
3. 重建数据清洗、统计和作图代码；对含糊步骤记录假设，不静默补全。
4. Reviewer 独立核对样本数、单位、轴变换、统计检验和图注。
5. 使用 numeric tolerance 或语义 JSON 比较关键输出，并冻结复现报告。

**最终产物**

- 重建图、脚本、结构化 claim 表、原图与重建图差异说明；
- 每个数字的来源定位；
- `reproduced / partially reproduced / not reproduced` 分项结论。

**验收标准**

- 不能把“视觉接近”当作复现成功；
- 每个未公开或无法确定的输入都进入 limitation；
- 重建脚本可在干净本地 workspace 中执行；
- 只评价指定 claim，不延伸为对整篇论文真伪的判断。

**为什么适合 Wisp**

这是把 PDF 阅读、精确证据绑定、代码执行、Artifact、Reviewer 和 clean verification
串起来的短而有力案例，特别适合录制 5–10 分钟产品演示。

## 4. 人在回路中的药物再利用迭代

**研究问题**

针对一个明确的细胞表型，能否从疾病机制和可用药理证据出发提出第一轮候选；在研究者
上传实验结果后，解释命中并设计信息量更高的第二轮候选？

**示例提示**

> 围绕“增强目标细胞的指定功能”建立机制假设，分别让文献 Agent、药理 Agent 和
> 反对证据 Agent 提出并审查 10 个已知小分子。实验由人执行；我上传盲化结果后，
> 再分析剂量反应、毒性和批次效应，提出第二轮候选及每个候选的判别性理由。

**演示路径**

1. 将疾病机制、可测表型、排除条件和成功阈值写成显式研究契约。
2. 多 Agent 并行寻找支持机制、反例、已知安全性和候选化合物证据。
3. 生成第一轮候选排序、实验矩阵和预注册分析计划。
4. 人类研究者执行湿实验并上传盲化 CSV；Wisp 只承担数据检查和预注册分析。
5. 解盲后解释命中、失败和不确定性，更新假设并提出第二轮候选。

**最终产物**

- 候选—机制—证据矩阵和实验设计表；
- 预注册统计计划、分析脚本、剂量反应图和下一轮决策记录；
- 每一轮之间可回溯的假设更新轨迹。

**验收标准**

- 第一轮分析计划在查看结果前冻结；
- 阴性结果、毒性和批次效应与阳性命中同等呈现；
- 第二轮候选必须说明它区分哪两个竞争机制；
- 案例不声称 Wisp 执行湿实验、发现疗法或提供临床建议。

**为什么适合 Wisp**

这是对 Robin 闭环最合理的开源、本地实现：不追求无人实验室，而是让 Project、Run、
Artifact、Decision 和 Evidence 保持跨轮次连贯。由于需要真实协作者，适合作为 P2 联合案例。

## 5. 为 T 细胞耗竭设计可审查的 CRISPR 筛选

**研究问题**

哪些基因最值得进入一个用于研究 T 细胞耗竭调控机制的 pooled CRISPR 初筛，如何在
有限文库规模内平衡已知阳性对照、探索性候选和必要对照？

**示例提示**

> 综合文献、通路、表达、遗传和已有 CRISPR screen 证据，提出 32 个候选基因。
> 支持证据和反对证据必须由独立 Agent 检索；给出候选评分、阳性/阴性对照、guide
> 设计检查项和统计 power 假设。不要把基因排名包装成生物学事实。

**演示路径**

1. 明确细胞模型、耗竭 readout、扰动类型、文库规模和不允许的实验假设。
2. 文献、通路、公开 screen 和表达证据并行检索，统一到 gene-level evidence table。
3. 候选评分显式分开证据强度、机制新颖性、可扰动性和潜在 viability confounding。
4. 设计对照结构、replicate/power 假设、guide QC 与 hit calling 计划。
5. Reviewer 寻找遗漏的已知 regulator、循环论证、数据泄漏和不可检验候选。

**最终产物**

- 32 基因候选表及逐项来源；
- controls、guide 设计检查表、样本布局和预注册分析计划；
- 一张从候选证据到 readout 的研究设计图。

**验收标准**

- 已知阳性对照与探索性候选分层报告；
- 每个候选至少绑定一条可核查证据，缺乏证据的候选明确标记为 hypothesis；
- power 和 hit calling 参数可由模拟脚本重算；
- 最终方案要求实验负责人批准，不自动进入实验执行。

**为什么适合 Wisp**

这是 Biomni 已证明用户容易理解的任务类型，但 Wisp 可以用
[受控多 Agent 工作流](agent-delegation.md)、真实检索、Decision 和预注册 Run 把“为什么选”
呈现得更透明。

## 6. 从非编码变异到功能机制优先级

**研究问题**

给定一个疾病相关 locus 的候选非编码变异，哪些变异最可能影响目标组织中的调控活性，
哪些机制值得优先实验验证？

**示例提示**

> 在本地读取合成 VCF；用公共注释、eQTL/染色质证据、保守性和文献建立候选表。
> 公共证据和机制解释分开报告，只用于研究优先级，不作临床诊断。

**演示路径**

1. 本地解析 VCF，检查 genome build、等位基因方向和坐标规范化。
2. 查询公开数据库，建立 tissue-aware annotation table，并记录版本和缺失值。
3. 用文献综述核对靶基因、组织和已知机制，标出一致、冲突和证据不足的区域。
4. 生成 top variants、建议验证 readout 和不确定性说明。

**最终产物**

- 规范化变异表、注释矩阵和证据图；
- 变异—靶基因—组织—证据的机制网络；
- 研究优先级报告和验证实验建议。

**验收标准**

- 原始 VCF 不离开本地；
- genome build、strand 和 reference allele 全部通过确定性检查；
- 不把注释分数解释为致病概率；
- 文档醒目标注 research-use-only，禁止临床个体结论。

**为什么适合 Wisp**

该案例能同时展示秘密/敏感输入的本地边界、公共 MCP 检索和文献证据，
比普通“解释一个 VCF”更符合 Wisp 的控制面定位。

## 7. 从公开结构到可引用的功能位点报告

**研究问题**

对一个公开蛋白结构，能否整理出可引用的功能位点、文献证据和局限说明，
而不是只展示一张结构图？

**示例提示**

> 以公开 PDB/UniProt 条目为起点，整理催化/界面位点、文献证据和许可信息，
> 用 figure-composer 出位点表与示意，paper-narrative 写 Methods 和局限。

**演示路径**

1. 从 PDB/UniProt 拉取结构、序列、功能位点和许可信息。
2. 将位点定义、证据来源和排除规则写成可检查的表格。
3. 用文献核对每个位点的实验支持，标出推断与已验证的区别。
4. Reviewer 检查是否存在选择性汇报，最后只保留有出处的位点。

**最终产物**

- 位点表、结构示意和文献证据矩阵；
- Methods 段落与局限说明；
- 一条 Decision：哪些位点可以写入正文。

**验收标准**

- 每个保留位点绑定可核查出处；
- 许可与数据来源写进报告；
- 明确区分实验观测与计算推断。

**为什么适合 Wisp**

该案例把 MCP 检索、文献证据、作图和叙事收在同一条可复现链路上。

## 8. 从靶点到可解释的活性分子短名单

**研究问题**

对一个结构已知的靶点，能否从公开活性化合物出发建立一个小型、可审查的短名单，
把候选压缩到值得进一步讨论或实验的集合？

**示例提示**

> 从 ChEMBL/PubChem 收集目标靶点的活性分子，统一结构和单位，按相似性和理化属性
> 选取 100–500 个代表分子，形成短名单。不要把计算描述符当成亲和力或成药性。

**演示路径**

1. 确认靶点构建体、物种、assay 类型和活性单位，清洗并去重公开分子。
2. 记录纳入/排除规则，生成可重建的小型化合物表。
3. 用结构多样性、理化属性和公开 assay 证据进行多维排序。
4. Reviewer 抽查质子化/互变异构、assay context 和数据泄漏。

**最终产物**

- 标准化分子表、筛选规则和属性矩阵；
- top candidates 的结构图与逐项选择理由；
- 清楚区分已知活性证据和待验证假设的报告。

**验收标准**

- 分子身份、活性单位和 assay context 可追溯；
- 淘汰规则完整报告；
- 至少保留一定化学多样性，避免 top list 全是近邻类似物；
- 不声称描述符等于亲和力、ADMET 或临床可行性。

**为什么适合 Wisp**

这个故事把约 80 个生物数据库 MCP、作图和科学边界说明
放在同一条可复现链路中，比单独展示“画出一个分子”更可信。

## 9. 一条争议性结论的正反证据地图

**研究问题**

以“清除衰老细胞能够改善骨骼肌再生”为例，现有证据在哪些模型、干预和终点上成立，
又在哪些条件下冲突或缺失？

**示例提示**

> 对这个 claim 做正反双方独立检索。Supporting Agent 只找最强支持证据，
> Challenging Agent 专找反例、边界条件、失败重复和方法学问题；Extraction Agent
> 提取模型、样本量、干预、终点和效应量；Reviewer 抽查引用与数字；最后生成证据地图，
> 不做简单多数表决。

**演示路径**

1. 把宽泛 claim 拆成物种、疾病/年龄模型、干预类型、组织和终点。
2. 支持与挑战 Agent 独立检索，避免共享中间结论造成确认偏差。
3. 对纳入论文做结构化提取，记录原文定位和无法比较的原因。
4. 生成 evidence matrix、研究设计分层和定量 cross-study figure；不适合合并时拒绝伪 meta-analysis。
5. Actor 写结论，Critic 核对引用、数字和措辞强度，保留未解决分歧。

**最终产物**

- PRISMA 风格检索记录、evidence matrix 和正反证据地图；
- 按模型/干预/终点分层的图；
- “最强支持、最危险反例、证据空白、下一步实验”的平衡结论。

**验收标准**

- 每个引用真实存在，关键结论能回到原文位置；
- 反方检索不是在支持结果上附加一段 caveat；
- 不以论文数量代替证据质量，不合并不可比终点；
- Reviewer 抽样核验通过，并公开遗漏、访问限制和截止日期。

**为什么适合 Wisp**

Wisp 已有 Literature evidence review、Roundtable 和 `literature-review`；bear-* Skills 可从技能商店的 BEAR Research Skills 来源按需安装。
此案例能证明[多 Agent](agent-delegation.md)的价值在于独立取证、结构化交接和审阅，
而不是让多个模型重复生成相似文字。

## 10. 在两种数值方法之间做可复现的科学决策

**研究问题**

对于一个带已知守恒量的二维反应扩散系统，显式有限差分与谱方法在相同误差预算下，
哪个方案更稳定、更高效、更适合作为后续大规模参数扫描的主线？

**示例提示**

> 从同一初始条件和边界条件创建两个探索分支：有限差分与谱方法。先写验证用的
> manufactured solution 和守恒/收敛测试，再运行分辨率扫描。比较误差、稳定性、
> wall time 和内存；只有通过验证的实现才能进入性能比较。

**演示路径**

1. 将方程、无量纲参数、边界条件、初始条件和容差写成机器可读配置。
2. 两个分支独立实现求解器，并共享同一验证数据与指标。
3. 先跑收敛阶、守恒量和稳定性测试，再做性能与参数扫描。
4. 需要时把扩大后的扫描作为 SSH-direct Run 执行，并收获结果到项目。
5. 生成精度—成本 Pareto 图和方法 Decision，Reviewer 复核比较是否公平。

**最终产物**

- 两个求解器、测试、配置、环境快照和参数扫描结果；
- 收敛图、守恒误差图、Pareto 图和方法选择记录；
- 可在本地小规模重跑的 Evidence Capsule。

**验收标准**

- 两种方法使用相同方程、初值、终止条件和误差定义；
- 未通过收敛或守恒测试的实现不得仅凭速度获胜；
- 随机性、硬件与线程数被记录；
- 结论限制在测试参数域内，不泛化到所有 PDE。

**为什么适合 Wisp**

这是一个刻意脱离生物医学的案例。它不依赖专有数据库，只依赖 Python/R、文件、Run、
SSH、探索分支、Reviewer 和 Evidence Capsule，可以验证 Wisp 的底层抽象确实服务于
一般科学计算，而不是一组生物信息学快捷入口。

## 推荐落地顺序

### 第一阶段：三支可信的旗舰演示

1. **GEO → Evidence Capsule**：复用现有 seed，最短时间形成端到端故事。
2. **论文图复现与 claim 审计**：数据小、演示短，突出证据与复现能力。
3. **远端单细胞方法分支比较**：完整展示本地优先、SSH/GPU 和探索分支。

### 第二阶段：领域能力演示

4. CRISPR 筛选设计。
5. 蛋白序列设计与独立复核。
6. 小分子虚拟筛选。
7. 正反证据地图。

### 第三阶段：联合研究与跨领域验证

9. 与遗传学团队合作非编码变异优先级。
10. 发布一个非生物医学的数值模拟案例。

## 每个正式案例都应遵循的模板

正式发布时，每个 case study 至少包含以下内容：

1. **Problem**：一个研究者真实会问的问题，以及为什么现有流程费时或容易出错。
2. **Inputs**：数据来源、许可、checksum、规模和是否允许公开。
3. **Research contract**：评价指标、停止条件、审批点和预先声明的限制。
4. **Wisp trajectory**：使用的 Project、Execution Context、Skills、MCP、Agents 和 Runs。
5. **Decision points**：人类在哪里批准、否决或改变方向，为什么。
6. **Outputs**：代码、图、表、报告、环境快照和 Evidence Capsule。
7. **Verification**：确定性检查、Reviewer 结果、干净重跑和人工 spot check。
8. **What failed**：失败 Run、被拒绝假设、不可访问数据和未解决的不确定性。
9. **Measured outcome**：时间、人工步骤、重跑成功率或错误发现数；没有基线就不写“快 100 倍”。
10. **Reproduce it**：固定版本、最小命令、预期输出，以及无需真实 SSH/GPU 的小型 mock 路径。

最重要的写作原则是：**展示 Wisp 如何让科研过程更可检查，而不是暗示 Agent 已经替代了
科学验证。** 一个可信的阴性结果、失败复现或被 Reviewer 否决的候选，往往比一句
“AI 发现了新机制”更能说明产品价值。
