# Wisp Lab 课题组

[English](wisp-lab.md)

一台 `wisp-relay` 可以服务任意多台互不相干的电脑。Wisp Lab 是建立在它之上的可选功能：
共用同一台中继的电脑组成一个课题组，有一位组长、一份经审核的成员名单、一个共享知识库，
以及让各成员的 Agent 互相写信的信箱。

中继仍然只是基础设施。它保存“谁在组里”和“谁给谁写过信”。课题组密钥从不到达中继，
所以它读不了知识库，也读不了任何一封信。

## 在中继上开启

是否开启课题组在部署中继时决定。在[中继部署](remote-access.md#deploy-the-relay)的基础上
多加一个环境变量：

```bash
export WISP_LAB=1
```

使用 Docker Compose 时，在中继的 `environment` 下加一行 `WISP_LAB: "1"`。

不设这个变量时，所有 `/v1/lab/*` 路由都返回 404，`lab/` 目录不会被创建，
使用这台中继的电脑彼此互不知晓。项目同步和网页远程访问不受这个开关影响。

课题组数据保存在 `WISP_RELAY_ROOT` 下的 `lab/` 目录：`state.json` 存成员、
未使用的校验码和知识库指针，`inbox/` 存尚未取走的信件。请和中继的其他数据一起备份。
之后关掉这个变量只会隐藏课题组，不会删除数据。

## 角色

- **第一台加入的电脑创建课题组并成为组长。** 部署中继的人应在开启后立刻加入：
  在此之前，任何持有中继令牌的人都可能抢先成为组长。
- **其他人需要组长发的校验码**，加入后处于“待审核”状态，直到组长通过。
  待审核的成员只能看到课题组名称，看不到成员名单、知识库和信件。
- **组长**负责生成校验码、通过或拒绝申请、移除成员、发布知识库。
- **成员**可以退出。组长不能退出，目前也不能转让组长身份。

一个校验码只能加入一人，七天后失效。校验码内含课题组密钥，请像密码一样对待。
它不包含中继令牌：令牌需另行发送，和项目设备码的做法一致。

## 创建课题组

1. 以 `WISP_LAB=1` 部署中继。
2. 在桌面端打开 **设置 → 远程接入 → Wisp Lab 课题组**。
3. **校验码**留空，填写中继地址、中继的 `WISP_RELAY_TOKEN`、你的名字和课题组名称，
   点击 **创建课题组**。

你的电脑会生成课题组密钥和本机的成员密钥，并保存在操作系统凭据库中。你现在是组长。

要添加成员，点击 **生成校验码**，把校验码私下发给对方，再另外把中继令牌发给对方。
对方提交申请后会以“待审核”出现在 **成员** 列表里；点击 **通过** 放行，点击 **拒绝** 回绝。
之后可用 **移除** 把成员移出。拒绝和移除都需要在同一个按钮上再点一次确认。

## 加入课题组

1. 打开 **设置 → 远程接入 → Wisp Lab 课题组**。
2. 粘贴校验码。中继地址已包含在校验码里，该栏可以留空。填写中继令牌和你的名字，
   点击 **申请加入**。
3. 页面显示“待审核”。组长通过后，点击 **重新检查** 即可看到成员和知识库。

**退出课题组** 会把你从成员名单中移除，并删除本机的课题组密钥。重新加入需要新的校验码。

如果中继管理员更换了 `WISP_RELAY_TOKEN`，在 **中继访问令牌** 一栏填入新令牌并点击
**更新令牌**。如果组长移除了这台电脑，页面会给出提示，并提供 **清除本机记录**，
它只清除本机保存的密钥。

## 知识库

知识库就是一个普通的 Wisp 项目：由组长维护，其他人只读。

**组长。** 把课题组的实验方案、参考笔记和共用脚本放进一个项目，在项目卡片上点击
**立即同步** 让它出现在中继上，然后在 **知识库** 下选中它，点击 **发布为知识库**。
此后中继只接受你对该项目的修改。想让成员拿到更新时，再点一次 **立即同步**。

**成员。** 点击 **下载知识库** 并选择存放位置。它会成为你电脑上的一个项目，
在其卡片上点击 **立即同步** 即可拉取组长之后的修改。你在本机做的修改只留在本机：
中继会拒绝成员的推送，在同步对话框中选择 **采用远端版本** 可恢复为组长的版本。
想贡献内容，请把材料发给组长。

知识库下载后，Wisp 会在普通对话中告诉你的 Agent 这个文件夹的位置，
让它在回答课题组相关的问题前先查阅其中的方案和约定。

知识库通过[项目同步](project-sync.zh-CN.md)传输，而项目同步使用
**设置 → 常规 → 手动项目同步** 里的中继令牌。从未配置过项目同步的电脑在加入课题组时
会自动填入课题组的中继地址和令牌，所以 **立即同步** 可以直接使用。已有的同步配置不会被改动：
如果它指向另一台中继，需要先改为课题组的中继才能下载知识库。

## Agent 互通

各成员的 Agent 可以互相提问。双方不必同时在线：信件会留在收件人在中继上的信箱里，
等对方的电脑来取。

**接收。** 在 **Agent 互通** 下选择 **用于回复课题组来信的项目**。在你选择之前，
发给这台电脑的提问会自动收到一条“这台电脑不回复课题组来信”的说明，
这样不会有人白等一个不会来的答复。每位发件人在该项目中对应一条名为 *Lab: <名字>* 的对话。
来信到达后，你的 Agent 在这条对话里运行一个回合，答复会自动发回。
随信附带的文件保存在该项目的 `uploads/lab/` 下。

**提问。** 加入课题组后，你的 Agent 多了两个工具：

- `lab_members` 列出成员。
- `lab_send` 向一位成员提问，可附带当前项目中的最多四个文件。
  对方的 Agent 只能看到这条消息和这些文件，看不到你的对话。

所以你可以在任意项目对话里写：“问一下小林的 Agent，他们的 RNA-seq 流程用的是哪个参考基因组”。
答复稍后会以 `[Lab reply from 小林]` 开头的消息出现在同一条对话里，你的 Agent 接着往下做。

Wisp 运行期间每 15 秒检查一次信箱。如果你的电脑当时关着，等它下次启动时会处理等待中的来信。

### 来信能做什么

来自其他成员 Agent 的消息是同事写的文字，不是你写的。由它触发的回合，
无论在哪一方，都受以下限制：

- **改动先问。** 写文件、改文件、运行命令、使用内核以及其他会产生改动的工具，
  都需要你在桌面端批准，即使你的默认设置是允许。这和 IM 渠道的底线相同。
- **只读本项目。** Agent 只能读取和搜索这条对话所属的项目：
  也就是你为来信选定的项目，或者（对于答复）发出提问的那个项目。
- **只有少数工具免询问。** 读取、搜索和查看本项目的文件，加载技能，列出课题组成员，
  以及完成回答。其余一律先问，包括只读的工具：记忆搜索、浏览器、Run 状态，
  以及所有连接器（内置的和你自己配置的）。
- **不带全局记忆。** 这个回合不会注入你的全局记忆。
- **继续写信先问。** Agent 想在这样的回合里再给课题组写信，需要你批准，
  开着“完全权限”也一样。
- **最多连续四封。** 中间没有人发言时，一次交流最多是“问、答、问、答”，然后停下：
  Agent 会被要求向自己的用户汇总现状。由于每封后续信件本来就需要批准，
  这是那条规则之后的第二道防线。

对提问的自动答复是唯一不经你审阅就发出的内容。它是你的 Agent 依据你选定的项目写出的回答。
请选择一个你愿意与课题组讨论其内容的项目。

## 安全模型

- **每位成员两个密钥。** 中继令牌证明这台电脑可以使用中继；成员密钥
  （桌面端生成的 256 位随机数，保存在操作系统凭据库）证明它是哪位成员。
  中继只保存成员密钥的 SHA-256。
- **中继从不接触课题组密钥。** 它装在校验码里，由人传给人。知识库指针和每一封信
  在离开桌面端之前都用它加密（AES-256-GCM）。
- **校验码以哈希登记。** 组长的桌面端生成校验码中的随机数，只向中继登记它的 SHA-256。
  即使有人读到中继的磁盘，也无法凭哈希加入。
- **信件绑定收发双方。** 中继给每封信盖上经它认证的发件人，信件的认证数据里同时写明
  发件人和收件人。中继若把信投给别人，或冒名改写发件人，这封信就打不开。
- **只有组长能写知识库。** 它是一个普通的[同步项目](project-sync.zh-CN.md)。
  组长登记之后，中继拒绝其他任何人向该项目提交。成员用加密指针里的项目密钥读取。
- **附件是加密数据块。** 用 `lab_send` 发送的文件以课题组密钥加密，像同步数据块一样存放；
  信里带着它的哈希、大小和文件名。接收方会校验这三项，并用自己清理过的文件名
  写入 `uploads/lab/`。和项目同步一样，中继会一直保留这些数据块。
- **移除只吊销成员密钥，不更换课题组密钥。** 被移除的成员不能再查看成员、收新信或发信，
  但仍持有课题组密钥和中继令牌，所以仍可能拉取知识库的后续版本。
  要彻底切断，请更换 `WISP_RELAY_TOKEN` 并把新令牌发给留下的成员。

## 中继接口（面向贡献者）

所有路由都需要中继的 bearer 令牌；除 `join` 外，还需要在 `x-wisp-member` 头中携带成员密钥。
被拒绝的请求以一个简短的代码作为响应体，例如 `lab_disabled`、`unknown_member`、
`not_active`、`not_leader`、`invite_required`、`inbox_full`。

| 路由 | 谁可以调用 | 作用 |
| --- | --- | --- |
| `POST /v1/lab/join` | 持有令牌的任何人 | 创建课题组，或凭校验码加入 |
| `GET /v1/lab` | 成员 | 该成员能看到的课题组信息 |
| `POST /v1/lab/invites` | 组长 | 登记校验码随机数的哈希 |
| `POST /v1/lab/members/{id}/approve` | 组长 | 通过待审核成员 |
| `DELETE /v1/lab/members/{id}` | 组长，或成员本人 | 移除、拒绝或退出 |
| `PUT /v1/lab/knowledge-base` | 组长 | 发布加密的知识库指针 |
| `POST /v1/lab/members/{id}/mail` | 已通过的成员 | 给某位成员留一封加密信件 |
| `GET /v1/lab/mail` | 已通过的成员 | 最早的若干封待取信件 |
| `DELETE /v1/lab/mail/{id}` | 已通过的成员 | 确认收到一封信 |

信件在被确认之前一直留在信箱里，所以投递中断的信会再次投递。桌面端在信件对应的回合结束后
才确认，并在本次运行期间记住已处理的信件，因此确认丢失时只会重发确认，不会重跑回合。
桌面端若在回合中途退出，重启后会重新回答那封信。回合无法开始的答复，或没能发回去的回答，
同样留在信箱里，等下次启动再试，内容不会丢失。一封信加密后最大 256 KiB，
一个信箱最多存 500 封；附件以中继数据块的形式传输。中继端实现在
`crates/wisp-sync/src/lab.rs`，桌面端在 `src-tauri/src/channels/lab.rs`（成员管理）
和 `lab_mail.rs`（信件和两个工具）。

## 暂未包含

- 组长身份不能转让，组长不能退出。
- 没有群发：`lab_send` 一次只写给一位成员。
- 桌面端靠轮询取信，没有推送。
- 待审核的成员需要点击 **重新检查** 才知道已通过。
- 成员不能向知识库推送，贡献内容需经组长。
