# 研究历程 / Research journey

研究历程按日期展示一个项目中已经记录的研究活动。左侧原「研究图谱」入口现在打开「研究历程」；原有节点、关系和关系详情保留在「关系图」视图中。

## 使用

1. 打开项目，点击左侧「研究历程」。默认显示本月，最近有活动的一天展开，其他日期保留摘要和产物链接。
2. 日历上的小点表示已载入的活动日期。点击日期读取当天记录，使用「显示整月」返回月视图；左右箭头切换月份，「回到今天」回到当前月份。
3. 搜索框搜索当前加载范围内的标题、说明和日期。每次读取最多 2,000 条活动，超出时明确提示；可以选一天缩小范围。搜索不会联网，也不搜索尚未载入的其他月份。
4. 每天先加载三份产出的预览，更多产出可以展开。点击产出卡片，在右侧查看该历史版本、对应生成运行及已登记的输入。点击「打开产物」打开当时的版本；「查看运行记录」展示运行状态、命令及日志尾部。缺失的来源明确显示为未记录。
5. 点击「补充记录」，选择研究日期和进展、发现、决策或待继续，填写标题和说明。记录会保存在项目中；历史补记同时保留实际保存日期。
6. 每天卡片顶部可以「生成回顾」，见下文 [每日研究回顾](#每日研究回顾--daily-recap)。
7. 完成一个研究阶段后，在会话工具栏选择「研究归档」或输入 `/archive`。集中确认结论、代码与文件清单后，会话变为只读，所选本地文件永久删除。归档节点出现在研究历程中，可查看归档材料、原始实验记录或「继续研究」。详见 [研究阶段归档](research-archives.md)。

Escape 每次只关闭最上层：产物查看器、补充记录或运行详情、正在编辑的回顾、关系详情，最后返回原工作区。也可以通过右上角关闭按钮返回。

通过侧栏「返回项目」或命令面板「打开项目列表」回到首页时，研究历程会随项目视图一起关闭。再次进入项目后，可从侧栏重新打开研究历程，默认查看本月；旧的日期筛选和局部面板不会带回。即使从首页研究日历进入项目的请求尚未完成，先返回首页后，延迟结果也不会重新打开研究历程。

Returning to Projects from the sidebar or command palette closes the project’s
research journey. Reopening it starts in the current month. A delayed calendar
drill-down response cannot reopen the journey after you have returned home.

Windows 下研究历程位于集成标题栏下方，菜单和窗口控制按钮保持可用；使用原生标题栏的平台不额外留白。按日时间线和右侧来源栏、以及关系图列表不预留常驻滚动槽，滚动条叠在内容上、悬停时才显现，避免两条系统滚动条把版面切开。运行记录使用宽版弹窗，分区显示状态、运行环境、本地起止时间、退出码、执行命令及标准输出/标准错误的日志尾部。长命令和日志自动换行，内容在弹窗内滚动，关闭按钮始终可见；未记录的字段和空日志显示明确提示。

## 首页研究日历 / Home research calendar

首页右上角、收藏图标左侧的日历图标打开「研究日历」，汇总所有可见项目的**主线**研究活动。首页的项目管理和最近会话布局保持不变。点击「返回首页」或直接按 Escape 关闭日历；窗口级设置等上层界面会先消耗 Escape。

- 默认显示本月和今天。左右箭头切换月份（进入该月第一天），「今天」回到当前日期；点击日期后右侧按项目显示当天记录，窄窗口将详情放在日历下方。
- 左侧项目列表切换「所有项目」或单项目。项目颜色由 ID 稳定分配，左侧列表同时标示项目名称和颜色；同一会话在同一本地日期只显示一次。月份摘要统计有记录的项目数和活动日数，不代表研究完成度。
- 当天详情按项目分组，显示完整的已加载记录数；每组默认按时间从新到旧展示 8 条，可逐批「显示更早记录」或收起。点击项目标题折叠该组，长标题可「展开全文」。点击标题右侧的打开图标，打开该项目所选日期的研究历程，可继续查看准确产物版本、运行来源和其他记录。之后从项目侧栏重新打开研究历程，仍默认显示本月。
- 大屏下内容区随窗口扩展，超高窗口限制工作区高度以保持月历比例；项目列表、月历和当天详情分别滚动；日期与记录总数保持在详情顶部，项目标题在滚动时保持可见。窄窗口将详情放在月历下方，较矮窗口使用页面滚动。
- 日历只读取登记过的会话、运行、产物、文献、数据资产、决策和人工记录，不预测未来任务。项目当天已有每日回顾（草稿或已确认）时，回顾标题和「今日完成」显示在该项目记录上方；同一 Run 生成的产物折叠进该 Run 的记录，并显示产出数量。隐私模式隐藏的项目不会显示，也不会提交到日历读取请求中。未采用的探索分支私有记录不进入首页主线汇总。
- 月份和当天分别读取，每个项目每个范围最多 2,000 条事件。月份超限时明确提示标记可能不完整，点击任意日期可重新按日读取；当天仍超限也会提示。失败项目保留错误提示，统计标为「已读取」，不会把部分结果当作完整统计。点击右上角刷新图标可重试并更新活动。

接口 `get_research_calendar(projectIds, from, until)` 复用已有研究历程投影，不改变当前项目或活动探索分支，不创建新持久化表。时间范围使用本地日历计算，支持夏令时的 23/25 小时日。

手动检查：在两个项目各登记一条记录，从首页打开日历，选择日期并切换项目；点击项目标题右侧的打开图标确认进入对应日期的研究历程。开启隐私模式隐藏其中一个项目，再检查日历；分别验证浅色/深色、窄窗口和打开后立即按 Escape 返回首页。在 1920/2560 像素宽的大窗口选择记录较多的一天，确认详情独立滚动、项目折叠、逐批显示与长标题展开不会撑高整页。

## 日期和数据含义

- 日期按当前设备的本地时区分组，月份和日边界使用本地日历计算，兼容夏令时。切换设备时区后，接近午夜的活动可能属于不同的日历日。
- 会话按实际用户消息时间记录，同一个会话在同一天显示一次。这里只显示会话来源，不把消息自动归纳成科学结论。
- 同一天内开始并结束的 Run 只显示一行最终状态，并附上它生成的产出数量；跨日实验在开始日显示「开始」，在结束日显示结果。失败、取消和失去连接也作为研究活动保留。同一天的实验数量按 Run 去重。取回远程产出的传输任务（「Harvest run outputs」）属于后台操作，不再出现在研究历程中；产出仍归属于原 Run。
- 产出按 ArtifactVersion 的登记时间归组。今天登记一个历史文件，会显示为今天登记；只有存在明确生成 Run 时，来源区域才显示运行完成时间。历史卡片始终打开准确版本，不随最新版本变化。
- 文献、数据资产和决策按研究对象创建时间展示。更新已有对象不会凭空制造另一次历史事件。
- [研究职责](research-mandates.md)的每份汇报记为一条「进展」（标题「职责汇报 · 职责名称」，说明为汇报标题），每个求助请求记为一条「待继续」（标题「职责等你处理 · 职责名称」，说明为请求内容），因此也出现在首页研究日历、科研助理的日历和每日回顾的输入里。被新请求撤回的旧请求不显示。职责是本机状态，这些条目只在主线显示，不随项目导出。
- 人工补充内容标为「手动」，不代表系统已经验证其科学正确性。每日标题优先采用当天保留的回顾标题，其次是已记录的进展或决策，否则使用实际活动标题。

## 每日研究回顾 / Daily recap

研究历程是流水记录；每日回顾把一天的记录归纳为四段：**今日完成**、**发现与决定**、**问题与失败**、**待继续**。每一条都引用它所依据的记录，点击引用可打开对应的 Run 记录、准确产物版本、会话或研究记录。

- **生成**：每天卡片顶部点击「生成回顾」（已有回顾时点刷新图标重新生成）。科研助理页面的 [自动化](automation.md) 中内置的「每日研究回顾」默认开启，每天到设定时间（默认 09:00）后，为各项目最近 3 天中有记录、尚无回顾的日子起草。没有记录的日子不调用模型；已有或已忽略的回顾不会被自动覆盖。
- **输入**：当天主线的 Run（标题、状态、起止时间、失败时标准错误的末尾）、产出文件名及生成它的 Run、进展/发现/决策/待继续/文献/数据资产/归档记录，以及研究者在会话中发出的请求（每条前 300 字）。不读取完整对话和助手回复，输入有固定上限。
- **审阅**：新回顾是「AI 草稿 · 待确认」。可「确认」、编辑（每行一条；改动过的行不再引用原来源）或「忽略」。忽略后恢复当天原有摘要，也可以再次生成。确认后标为「AI 起草 · 已确认」，它仍是对记录的归纳，记录本身保持不变。
- **模型**：使用 **设置 → 专家 → Recap** 绑定的模型；未绑定时使用当前默认模型。提示词固定，不能修改。
- **范围**：回顾只覆盖主线；探索分支中不显示。模型返回不存在的引用会被丢弃；没有任何内容时报错，不保存空回顾。

Every day card can draft a recap (Done, Findings & decisions, Issues, Next) from
that day's recorded mainline activity. Each item cites the runs, output versions,
conversations or records it summarizes, and opens them on click. A recap stays an
"AI draft" until you confirm it; you can edit it (an edited line drops its
citations), regenerate it or dismiss it. The built-in daily automation on the home
Automation page drafts missing recaps every morning. The model is the Recap
specialist's (Settings → Specialists → Recap), or the active model when unbound.

## 持久化与范围

跨边界类型定义在 `wisp-dto::ResearchJourney*` 与 `ResearchRecap*`。`get_research_journey` 的结果在 `recaps` 中附带主线回顾；`generate_research_recap(from, until)` 为当前项目的一天起草回顾并覆盖当天已有回顾；`update_research_recap(edit)` 保存审阅结果。

每日回顾保存在 `research_recaps` 表中，每个项目每个本地日期一条（迁移 `0060_research_recaps`，幂等）。项目包导入导出包含回顾；同步指纹只在表中有回顾后才计入，升级本身不会改变已发布项目的指纹。`get_research_journey` 读取指定时间范围的投影；`get_research_journey_source` 读取准确产物版本的运行和输入；`add_research_journal_entry` 追加人工记录。

人工记录使用独立的 `research_journal_entries` 表，不把进展和发现混存成 Decision。迁移 `0054_research_journal` 幂等。项目包导入导出和同步指纹包含主线记录；旧项目包没有这张表也可导入。

探索分支只显示自己的记录和检查点冻结的主线对象，不显示同级分支的新内容。新的检查点包含人工记录的基线；采用分支时将其人工记录带回主线，丢弃分支时清理其私有记录。旧检查点不会追溯吸收后来写入的人工记录。

## 验证与边界

自动测试覆盖日期范围、跨日运行、精确版本、补记时间、项目/探索分支隔离、项目包传输、日历和搜索、错误恢复、以及立即按 Escape 的关闭顺序。界面测试通过 mock Tauri bridge 运行，无需模型、远程主机或 API key。

手动检查：用真实项目创建一个 Run 并登记产物，重新打开研究历程；选择产物验证预览与运行来源；补记前一个月的发现，关闭再打开后检查日期；在窄窗口及深色主题下确认可以访问日历、时间线和来源。

每日回顾只归纳已记录的内容，不验证科学结论；不将未注册文件或任意终端命令视为已登记成果，不提供周报导出或人工记录编辑/删除。日历标记反映已加载范围；来源信息完整程度取决于已有的 Run 输入输出登记。
